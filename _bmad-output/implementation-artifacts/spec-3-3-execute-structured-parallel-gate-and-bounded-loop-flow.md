# Story 3.3: Execute structured Parallel, Gate, and bounded Loop flow

**Source:** `_bmad-output/planning-artifacts/epics.md`, Story 3.3; Story 3.1 typed node and condition contracts. **Date:** 2026-09-29. **Status:** implementation specification.

## Goal and scope

A schema-2 lesson graph can execute a Parallel with owned child activations, evaluate its named results at the matching Gate, and execute a Loop's direct body child up to its positive maximum. The runner remains the only owner of graph transitions, public node completion, lesson state, and telemetry. Story 3.2's uncommitted Timeline path is preserved. Story 2.4 supplies only ownership boundaries, not acceptance criteria. Checkpoint/resume, editor redesign, scene changes, transport/schema changes, and legacy controllers are outside this story.

## Runtime contract

1. `ValidateForExecution` accepts authoring-valid Parallel, Gate, Loop, variable, and composite conditions. It rejects a Gate reachable as a normal entry or from an unrelated parent, owned children reachable by normal routing, nested structured children, and Parallel with multiple Timeline children sharing the one scene playback controller. Invalid graphs fail preflight before activation. Schema-1 behavior is unchanged.
2. A Parallel activation creates a unique cancellation scope and activation ID for each named direct child. It invokes child executors through the registry without letting children select graph edges or publish a second parent result. Child results must match their node and activation IDs. Unknown, duplicate, stale, and post-cancellation completions are ignored. A child exception or invalid result is a failed branch.
3. `AllSuccess` joins when all branches succeed, or fails when a branch fails and cancels siblings. `FirstCompleted` joins on the first valid terminal branch result and cancels siblings. The parent emits one result. Each branch result is recorded by configured branch ID for the matching Gate; cancelled branches cannot later change it.
4. A Gate consumes the named branch results produced by its owning Parallel once. `And` succeeds only if every named result is present and successful; `Or` succeeds if any named result is present and successful. Missing or duplicated results fail closed; a Gate never starts quest or dialogue work. The runner routes a successfully joined Parallel directly to its configured Gate through the validated structural edge.
5. A Loop starts its direct body child with a fresh activation and cancellation scope on every iteration. It evaluates its exit condition after each valid child result. If true, it returns Success and the runner routes directly to `ExitNodeId`. If false at the positive maximum, it returns Failed and follows the Loop's configured failure edge, if any. A child never follows its own outgoing edges. The runner counts node and structural edge visits per run, including each body iteration.
6. Edge and Loop exit conditions support Always, Status, Variable, and recursive Composite AND/OR. Variable comparison uses a typed runtime source of bool, int, float, or string. A scene `LessonGraphVariableStore` supplies serialized initial values and typed runtime setters through the installer; callers using `LessonGraphRunner.Configure` can inject another typed source. Missing or type-mismatched values evaluate false. Comparisons are ordinal for strings and exact for other primitives. The source is optional only for graphs without variable conditions; graphs requiring it fail preflight if unavailable. Preserve Phase-1 status-edge precedence and priority/list-order tie breaking.
7. Parent skip and timeout return `Skipped` and `Timeout`; abort, pause, and scene unload cancel all owned child scopes before the runner's existing terminal or pause handling. Cancellation wins over a result not yet committed. Child callbacks cannot change a later run. No waits may hang on an uncooperative child after cancellation; outstanding faults are observed.
