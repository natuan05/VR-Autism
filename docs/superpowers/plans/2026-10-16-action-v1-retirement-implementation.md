## Contracts decided by this plan

### Authoritative runtime policy

Create client-safe `D:/Lab/VRA-web/src/lib/lesson-runtime.ts` exporting:

- `type LessonRuntime = "lesson_graph_v2" | "quiz" | "exploration" | "legacy_hello_friend"`.
- `resolveLessonRuntime(lessonDocumentId: string, lesson: Record<string, unknown>): LessonRuntime`, throwing a typed unsupported-lesson error when no rule applies.
- `type LiveKitParticipantScope = { participant_role: "teacher" | "vr"; lesson_runtime: LessonRuntime; session_id: string; host_id: string }`.

Rules, in order: practical + numeric schema `2` -> `lesson_graph_v2`; quiz -> `quiz`; theoretical -> `exploration`; exact document `Greet_1` + practical + **schema absent** + exact stored `scene_name="HelloFriend"` -> `legacy_hello_friend`; otherwise reject. Schema 1, null, string `"2"`, unsupported/missing types, and other schema-missing practical lessons do not silently fall back. The first rule allows the user's future valid HelloFriend schema-2 migration without another permanent ID exception. No runtime choice comes from a client flag, identity prefix, scene suffix, or first packet.

All launch paths compare requested `scene_name` to the lesson's nonempty stored `scene_name` before minting a token or activating a pairing. Return explicit `SCENE_MISMATCH` / `UNSUPPORTED_LESSON_RUNTIME` errors (HTTP 400) without launch writes. Keep existing ownership, child assignment, idempotency, race, and cache checks.
