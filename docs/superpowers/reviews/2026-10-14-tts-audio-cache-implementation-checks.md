## Runtime configuration and deployment prerequisites

For the approved same-computer runtime-cache development path, use [the 2026-10-15 local setup guide](../guides/2026-10-15-tts-runtime-cache-local.md). It requires neither `TTS_PREVIEW_SERVICE_URL` nor the separate preview process. The following HTTPS deployment instructions still apply to production and physical headsets.

These are handoff instructions, not deployment actions performed by the agent.

1. Configure the existing web Firebase Admin credentials and `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`, plus existing LiveKit API key/secret. Supply a strong server-only `TTS_CACHE_SERVICE_SECRET` to the web backend and both Python processes.
2. Set Python `TTS_CACHE_BACKEND_URL` to the HTTPS web backend origin. Set web `TTS_PREVIEW_SERVICE_URL` to the HTTPS roomless service base URL, without `/generate`. Provider credentials remain server-side. The V2 worker still needs its existing Google credentials and Gemini configuration.
3. Run the V2 worker with `uv run src/agent_v2.py start`. Run the separate roomless service with `uv run python src/tts_preview_service_v2.py`; it binds `TTS_PREVIEW_HOST` (default `127.0.0.1`) and `TTS_PREVIEW_PORT` or `PORT` (default `8080`). Put it behind HTTPS and the intended service network. The legacy Dockerfile/agent command was preserved.
4. Set the serialized **Tts Cache Backend Url** on the Waiting Area `SceneMenuController` to the same HTTPS web backend before testing a cache-aware V2 launch. Unity receives the retained configuration through the authenticated session endpoint, not a second locally maintained profile list.
5. Inspect Storage IAM/rules before deployment: `tts-cache/v1/**` must not permit unauthenticated or client writes/reads that bypass the backend's signed access. There is no local `storage.rules` source in these repositories, and deployed IAM/rules were not inspected or changed. Confirm signing credentials and browser audio access for generation-pinned URLs. Retain cloud objects, including rejected epochs, in the first release.
6. Shared Firestore configuration is `tts_configuration/shared`; cache-aware launch seeds missing configuration using approved defaults. Editor profile listing only reads existing profiles and never seeds or writes them. Changes affect the next session; agent restart and token renewal retain the original session snapshot.

## Timing and ownership

The default foreground cache budget is 1500 ms (session configuration range 0–10000). It begins at the local miss, or before an invocation's first wait for pending launch reconciliation, and ends after validated clip readiness. Queueing, lookup, download, validation and decode use its remaining time. Snapshot fetch and launch inventory synchronization each have a five-second bound. Background READY admission runs only when playback/preparation and canceled-stream barriers are clear, has a ten-second total bound and cancels for a new foreground owner. No live stream-start timeout was introduced; the existing dialogue timeout remains authoritative.

VR authenticates server-role agent participants, current SDK incarnation and boot UUID. HELLO/reconciliation supplies the actual VR run and retains completed-opening evidence independently of later hints. A canceled stream remains muted until its correlated terminal or authenticated replacement; its old lease cannot release a newer owner. Local audio success, failure and cancellation have separate terminal outcomes. Voice Quest still completes through matched speech, the existing interaction quest or teacher skip.
